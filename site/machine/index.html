How it works

Three jobs, and a bouncer

Making a math worksheet is one hard problem wearing three coats: write the math, draw the picture, prove the answer. Then something has to refuse to print the page when one of them is wrong.

Job one

Writing the math

Not “type x squared.” A proper stacked fraction. A square-root sign that stretches over whatever’s underneath it. An integral. On paper, at print quality, in a file Amazon will accept.

We tested it by writing out 47 expressions, starting at a sixth-grade proportion and ending at the equation describing how light and matter interact. All 47 render. The only thing in that entire range the typesetter couldn’t do was one symbol used in particle physics, fixed with a single line.

Every font ends up embedded in the finished PDF — which is the thing print shops actually reject files for. That’s checked on every build, not assumed.

Job two

Drawing a picture that isn’t lying

Ask an image generator for a 47° angle and you get something near 60°. Ask for a number line and the tick marks get spaced by eye. Ask for a parabola and you get a smile.

A worksheet whose picture disagrees with its own answer key teaches a child something false — and on a paid product, that’s a refund and a one-star review. So no image model goes anywhere near a math figure.

The idea that makes it work

Figures are drawn from the same numbers that produce the answer. And then the drawing measures itself — it hands back every side length and every angle it actually drew, so the build can compare that against what the worksheet claims and stop everything if they disagree.

The picture has to pass a pop quiz about itself.

What it can draw today: number lines (with inequality shading, open and closed circles), coordinate planes with real function graphs, triangles and polygons with accurate labelled sides and angles, circles with radii and chords, 3-D solids with dimension labels, and the statistics set — bar, box, scatter, histogram, dot plot.

Job three

Proving the answer key

A parent marks their child wrong from our key. If we’re wrong, we didn’t embarrass ourselves — we told a kid they’re bad at math when they aren’t.

So nobody writes the answers. A computer algebra system computes them, and hands back both the answer and the way to print it, so the question on the page and the answer in the back physically cannot drift apart.

There’s a second piece: deciding whether a child’s answer means the same as the key. 1.5, 3/2 and 1½ are one answer wearing three coats, and a key that only matches its own spelling marks a right kid wrong.

Three independent checks have to agree. If they disagree, it does not guess — it stops and asks a human. That triage bucket is the whole quality mechanism, and it costs nothing.

The bouncer

Ten gates. Any red one stops the build.

Every one of these exists because it caught something real.

$ node build-proof.mjs PASS triangle side labels match the drawing PASS the right angle really measures 90 PASS interior angles sum to 180 PASS Pythagorean answer equals the drawn hypotenuse PASS plotted line has the slope the key claims PASS cylinder volume key matches its printed labels PASS cylinder figure is declared NOT TO SCALE PASS box plot median is computed, not eyeballed PASS every problem's math parses PASS no page overflows its printable area GATE: 10/10 passed

Plus three that run inside the figure drawer: no two labels printed on top of each other, no text cropped off the edge of a figure, and every font in the finished PDF real and embedded.

The lesson that cost the most

Green checks lied. Looking didn’t.

Every defect that would have reached a customer was found the same way: by rendering the page and putting eyes on it. A missing right-angle mark. “6 cm” printed on top of the line it labelled. Shading so faint the answer was invisible. Two pages silently chopped off. Units deleted from a question — a cylinder labelled h = 9 cm printing as h = 9, which makes it a different question than the one the answer key answers.

Every one of those shipped through a green build.

The rule

A gate is worth having because it catches a defect once and then catches it forever. But a gate can only check what someone thought to check. The eye finds the thing nobody thought of; the gate makes sure it never comes back. Both, in that order, or you’re shipping blind.

Where it lives

The parts

FileWhat it does
build-proof.mjsEnd to end: draw the figures, compute the answers, run every gate, build the PDF.
lib/tex.mjsTurns math notation into something printable. Bundles its own fonts, so a page works offline.
lib/draw.pyDraws every figure — and measures each one back.
lib/cas.pyComputes the answer key. Nobody types an answer.
lib/equiv.pyDecides whether a child’s answer means the same as the key.
lib/overflow.mjsMeasures every page against the paper’s real edge.
font-gate.pyRun before any book ships. Checks the fonts are real fonts.
inspect-pdf.pyTurns the finished PDF back into pictures so a human can look.
selftest.mjsWhat the answer-matcher gets right — and what it can’t do.
